## 현재 구조 — 송출 방식 2가지 (사용자와 합의됨 — 바꾸기 전에 물어볼 것)

| | **로컬 송출** `/local` (예배용 기본) | **인터넷 송출** `/control/:code` (가끔) |
|---|---|---|
| 상태의 원본 | 이 PC (localStorage `biew.live.v1:LOCAL`) | **서버** `channels.state` |
| 컨트롤러 → 출력 창 | BroadcastChannel (서버 없음) | 같음 — PC 가 화면을 먼저 바꾸고 서버에 올림 |
| 다른 PC·폰 | 접근 불가(완전 로컬) | 리모컨(컨트롤 비밀번호)·보기(보기 비밀번호 선택) |
| 인터넷 끊김 | 무관 | PC 송출은 계속(경고 표시), 리모컨·보기만 멈춤. 다시 연결되면 **PC 기준으로 서버를 덮어씀**(force) |
| PC 꺼짐 | 송출 없음 | 리모컨 명령은 서버가 적용 → 보기 기기는 계속 동작. PC 를 다시 켜면 서버 상태를 이어받음 |

- **앱 자체**는 PWA 로 PC 에 저장 → 한 번 온라인에서 열어 두면 인터넷 없이도 열림(새 버전은 알림 후 적용, /output 엔 알림 안 뜸).
- **로그인은 저장하지 않는다**(새로고침 = 로그아웃). 로그인이 필요한 일: 곡 다운로드/곡 편집 올리기, 인터넷 송출 채널 만들기·관리(리모컨 쫓아내기·보기 비밀번호·삭제), 다른 PC 를 호스트로 등록.
- **인터넷 송출 호스트 PC 권한** = 채널 전용 **호스트 토큰**(`biew.host.<code>`, 로그인 아님). 채널을 만들 때/로그인해서 열 때 발급. 30일 미사용이면 서버가 거부 → PC 에 "권한 만료 — 로그인" 표시(PC 송출은 계속). **관리 기능은 호스트 PC 를 끊지 않는다**(예배 중 다시 로그인할 일 없게). PC 를 잃어버렸으면 채널 삭제.
- **채널 관리**(📡 → 관리, 그때 로그인): "모든 기기 접속 끊기"는 없앰(사용자 결정). 대신
  - **리모컨 모두 쫓아내기 = 컨트롤 비밀번호 변경**(새 비밀번호 필수, 같으면 거부) → 리모컨 토큰 무효 + 리모컨 주소 재발급. 쫓겨난 폰은 다음 조작부터 서버가 거부(조작마다 토큰 확인 — 수 ms). 호스트 PC·보기는 그대로.
  - **보기 비밀번호 설정·변경·없애기** → 설정·변경이면 보기 토큰 무효 + 보기 주소 재발급(보기 기기는 30초 안에 비밀번호 화면). 호스트 PC 그대로.
  - 다른 기기에서 했어도 방송실 PC 는 30초마다 서버를 확인해 새 주소로 다시 연결(로그인 불필요).
- **반응 속도**(측정): PC 직접 조작 = 즉시(서버를 기다리지 않음). 리모컨 → 보기 기기 약 0.12초, 리모컨 → PC 송출(프로젝터) 실제 브라우저 약 0.3초(테스트 확인 간격 0.25초 포함). 폰이 와이파이·LTE 면 0.05~0.2초 더.
- **리모컨 권한**: 송출 조작만(◀▶·곡 이동·슬라이드 점프·BLANK). 곡·콘티·스타일 수정, FREEZE, 채널 관리 불가. 명령은 서버가 검사·적용(`remote_command` → `_apply_command`, 앱 `nav.ts` 와 같은 규칙 — 검증 스크립트가 무작위 120건 대조).
- **실시간 알림**: 변경한 쪽(PC/리모컨)이 view·control 주소로 직접 보낸다. **호스트 PC 는 알림 내용을 믿지 않고 서버에서 다시 읽는다**(리모컨도 같은 주소에 보낼 수 있어 가짜 콘티를 섞을 수 있으므로). 리모컨은 control 주소에서만 상태를 받는다. 보기 기기는 표시만.
  - DB 발 공개 알림(`realtime.send`, private=false)은 기록만 되고 **공개 구독자에게 전달되지 않는다**(검증으로 확인) → 쓰지 않음(마이그레이션 20261118010000).
- **비밀번호 실패 잠금 = 그 기기(브라우저)만**(5번 틀리면 1분). 서버는 잠그지 않는다 → 다른 폰이 덩달아 잠기지 않음. **인지된 위험(사용자 결정 B)**: 스크립트로 4자리 비밀번호를 대입하면 막지 못한다.
- 비밀번호 최소 4자 유지(사용자 결정).
- **로컬 송출 운영**: 컨트롤러는 한 PC 에 한 창(두 번째 창은 경고, Web Locks — 먼저 연 창이 닫히면 이어받음). 다른 기기는 접근 불가.
  - **송출 종료** 버튼: 콘티·위치·BLANK·FREEZE 비움, **출력 설정 유지**, **출력 창은 닫지 않고 검은 화면**(전체화면 창을 닫으면 프로젝터에 바탕화면이 보이므로). 예배 2~3개인 날: 송출 → 송출 종료 → 다음 콘티 → … (출력 창은 처음 한 번만). 실수로 닫거나 새로고침한 건 이어짐.
  - **🌐 인터넷 송출로 전환**: 채널 이름(오늘 날짜로 미리 채움)·비밀번호 → 로그인 → 새 채널 생성 → 지금 송출(콘티·위치·FREEZE·설정)을 그대로 옮김 → **출력 창은 새로고침 없이 화면 유지한 채 새 채널로 갈아탐**(`switch-channel` 메시지) → 📡 창 자동으로 열림. 로컬 콘티는 비움. 반대 방향(인터넷→로컬)은 없음(사용자 결정 — 인터넷이 끊겨도 PC 송출은 계속되므로).
  - 인터넷 송출에는 "송출 종료" 없음(채널 삭제로 충분, 사용자 결정).
- 화면 용어 한글화: 송출 중(PGM) · 미리보기(PVW) · 송출(TAKE) · "미리보기 후 송출"(PVW 모드).
- 다른 기기에서 리모컨 쫓아내기 → 방송실 PC 는 **10초 주기** 확인으로 새 주소를 따라감(측정 1~6초. 30초 주기였을 땐 21~42초로 들쭉날쭉해 10초로 줄임). 컨트롤러 창을 최소화·오래 가려 두면 브라우저가 타이머를 늦춰 더 걸릴 수 있음.
- **송출 배경**(출력 설정): 검정(루마키)·초록(크로마키) 빠른 버튼 + 커스텀 단색 + 2색 그라데이션(↓ → ↘ ↙, ⇄ 색 바꾸기로 반대 방향). 키잉용이 아닌 배경엔 "ATEM 키잉 불가" 경고. 구조는 `shared/backdrop.ts` 의 `Backdrop`(kind: solid|gradient) — **배경 이미지는 나중에 kind:'image' 로 추가할 수 있게 열어 둠**(사용자 결정: 지금은 안 함. 오프라인 위해 PC 저장 필요). 예전 `background: black|green` 은 불러올 때 자동 이전.
- **홈 채널 목록**(로그인 불필요):
  - **이 기기의 채널**: 이 기기가 호스트(PC)·리모컨·보기로 들어간 채널(역할 표시, 누르면 저장된 입장 정보로 바로, ✕ 로 지우기 — 지우면 그 역할의 입장 토큰도 지움).
  - **공개 채널**: **보기 비밀번호가 있는 채널만**, 최근 7일 안에 사용된 것만(`list_public_channels`, 제목·번호·사용 시각만). 비밀번호 없는 채널은 QR·링크·번호로만(번호가 곧 열쇠라 목록에 안 올림 — 사용자 결정).
  - **제목 검색**: 대소문자·띄어쓰기 무시 + 한글 조합 통일, 포함 검색(`shared/searchText.ts`). 세 목록 모두.
  - 채널 번호 입력은 원래 대소문자 무시(입력·주소·서버 모두 대문자로).
- **콘티는 그날 하루 쓰는 임시 데이터** — 콘티 보관·다른 송출에서 가져오기 기능은 만들지 않는다(사용자 결정). 인터넷 송출은 서버에 '현재 상태'(콘티 포함)가 있으므로 나중에 필요하면 그걸로 가능성은 열려 있음.
- 곡: "곡 다운로드"(그때 로그인)로 PC 에 저장. PC 에서 고치거나 등록한 곡은 "서버에 올리기"에서 중복(가사 === / 제목 ===)·충돌(서버 updated_at) 검사 후 올림. 삭제는 온라인만.

## 새 컴퓨터에서 이어서 작업하기
```bash
git clone https://github.com/wondaero/biew.git && cd biew
nvm install 22 && nvm use          # Node 22 (.nvmrc)
npm install
```

**1. `.env` 만들기** (키 값을 화면에 내지 않고 바로 파일로):
```bash
npx supabase@2 login               # 브라우저 인증 — 이 프로젝트가 있는 계정인지 확인
npx supabase@2 projects api-keys --project-ref bgfkodbfgjhsauwqhviq -o json | node scripts/make-env.mjs
```
- CLI 는 **반드시 `npx supabase@2`**. CLI 3.x 는 `supabase/config.toml` 의 `[inbucket]` 때문에 실행을 거부한다 — config.toml 은 고치지 말 것(`config push` 사고 이력).
- 대시보드로 해도 된다: Project Settings → API Keys 의 **publishable** → `VITE_SUPABASE_ANON_KEY`, Legacy 탭 **service_role** → `SUPABASE_SERVICE_ROLE_KEY`(스크립트 전용, VITE_ 금지). `.env.example` 참고.
- 웹앱 화면만 고칠 거면 service_role 은 없어도 된다. `.env` 가 아예 없으면 앱은 뜨지만 로그인·곡·채널이 안 된다.

**2. DB 연결·상태 확인**(DB 를 건드릴 때만):
```bash
npx supabase@2 link --project-ref bgfkodbfgjhsauwqhviq
npx supabase@2 migration list --linked        # 로컬=원격 이면 대기 중인 것 없음
npx supabase@2 db push --linked --dry-run     # 새 마이그레이션을 만들었다면 먼저 확인
npx supabase@2 db push --linked               # config push 는 절대 금지
npx supabase@2 db query --linked "select ..." # 원격 SQL 조회(가사 본문은 출력 금지)
```

**3. 확인 명령**
```bash
npm run dev                # http://localhost:5173/
npm run typecheck && npm test && npm run build
npm run verify:channels    # 실제 DB 검증(임시 계정·Lorem 채널 만들고 정리) — 66개
npx vite preview           # 서비스 워커(PWA)는 배포용 빌드에서만 동작 — 오프라인 확인은 이걸로, 서버를 실제로 꺼서
```
- **브라우저 E2E**(`scripts/e2e/`, puppeteer-core + 설치된 Chrome): `npm run e2e` = 배포용 빌드 후 7종 전부(약 10분), 개별은 `npm run e2e:internet | local | home | bg | ime | offline | upgrade`, 지연 측정 `npm run e2e:latency`.
  - 개발 서버(5179)·미리보기 서버(5180·5181)는 스크립트가 알아서 띄우고 끈다. Chrome 을 못 찾으면 `CHROME_PATH` 환경변수로 지정. 스크린샷은 `out/e2e/`(git 제외).
  - **운영 Supabase 를 쓴다**: 임시 스태프 계정·Lorem 채널·테스트 곡을 만들고 끝나면 지운다(곡은 완전 삭제). `.env` 의 service_role 필요.
  - 다른 기기에서 리모컨 쫓아내기 확인은 호스트 탭을 앞에 둔다(뒤로 간 탭은 브라우저가 타이머를 늦춤).

**4. 배포·버전 확인**
- `main` 에 push → Vercel 자동 배포(1~2분). 브라우저는 앱 파일을 저장(PWA)하므로 **새로고침만으로는 새 버전이 안 열린다** → 왼쪽 아래 "새 버전 있음 — 지금 적용"(또는 홈 하단 버전 옆 버튼), 안 보이면 Biew 탭·창을 전부 닫고 다시 열기, 급하면 Ctrl+Shift+R.
- **홈 하단의 "버전 (빌드 시각) · (커밋)"** 으로 지금 열린 버전을 확인(`git log --oneline -1` 과 비교).
- 문제가 생기면 Vercel 대시보드 → Deployments → Instant Rollback.

가사 원본(.gcg 폴더)은 git 에 없다. 재import 가 필요할 때만 USB 등으로 복사(`doc/` 아래에 두면 자동으로 git 제외).
