## 현재 구조 — 송출 방식 2가지 (사용자와 합의됨 — 바꾸기 전에 물어볼 것)

| | **로컬 송출** `/local` (예배용 기본) | **인터넷 송출** `/control/:code` (가끔) |
|---|---|---|
| 상태의 원본 | 이 PC (localStorage `biew.live.v1:LOCAL`) | **서버** `channels.state` |
| 컨트롤러 → 출력 창 | BroadcastChannel (서버 없음) | 같음 — PC 가 화면을 먼저 바꾸고 서버에 올림 |
| 다른 PC·폰 | 접근 불가(완전 로컬) | 리모컨(컨트롤 비밀번호)·보기(보기 비밀번호 선택) |
| 인터넷 끊김 | 무관 | PC 송출은 계속(경고 표시), 리모컨·보기만 멈춤. 다시 연결되면 **PC 기준으로 서버를 덮어씀**(force) |
| PC 꺼짐 | 송출 없음 | 리모컨 명령은 서버가 적용 → 보기 기기는 계속 동작. PC 를 다시 켜면 서버 상태를 이어받음 |

- **앱 자체**는 PWA 로 PC 에 저장 → 한 번 온라인에서 열어 두면 인터넷 없이도 열림(새 버전은 알림 후 적용, /output 엔 알림 안 뜸).
- **로그인은 저장하지 않는다**(새로고침 = 로그아웃). 로그인이 필요한 일: 곡 다운로드/곡 편집 올리기, 인터넷 송출 채널 만들기·관리(리모컨 쫓아내기·보기 비밀번호·삭제), 다른 PC 를 호스트로 등록.
- **인터넷 송출 호스트 PC 권한** = 채널 전용 **호스트 토큰**(`biew.host.<code>`, 로그인 아님). 채널을 만들 때/로그인해서 열 때 발급. 30일 미사용이면 서버가 거부 → PC 에 "권한 만료 — 로그인" 표시(PC 송출은 계속). **관리 기능은 호스트 PC 를 끊지 않는다**(예배 중 다시 로그인할 일 없게). PC 를 잃어버렸으면 채널 삭제.
- **채널 관리**(📡 → 관리, 그때 로그인): "모든 기기 접속 끊기"는 없앰(사용자 결정). 대신
  - **리모컨 모두 쫓아내기 = 컨트롤 비밀번호 변경**(새 비밀번호 필수, 같으면 거부) → 리모컨 토큰 무효 + 리모컨 주소 재발급. 쫓겨난 폰은 다음 조작부터 서버가 거부(조작마다 토큰 확인 — 수 ms). 호스트 PC·보기는 그대로.
  - **보기 비밀번호 설정·변경·없애기** → 설정·변경이면 보기 토큰 무효 + 보기 주소 재발급(보기 기기는 30초 안에 비밀번호 화면). 호스트 PC 그대로.
  - 다른 기기에서 했어도 방송실 PC 는 30초마다 서버를 확인해 새 주소로 다시 연결(로그인 불필요).
- **반응 속도**(측정): PC 직접 조작 = 즉시(서버를 기다리지 않음). 리모컨 → 보기 기기 약 0.12초, 리모컨 → PC 송출(프로젝터) 실제 브라우저 약 0.3초(테스트 확인 간격 0.25초 포함). 폰이 와이파이·LTE 면 0.05~0.2초 더.
- **리모컨 권한**: 송출 조작만(◀▶·곡 이동·슬라이드 점프·BLANK). 곡·콘티·스타일 수정, FREEZE, 채널 관리 불가. 명령은 서버가 검사·적용(`remote_command` → `_apply_command`, 앱 `nav.ts` 와 같은 규칙 — 검증 스크립트가 무작위 120건 대조).
- **실시간 알림**: 변경한 쪽(PC/리모컨)이 view·control 주소로 직접 보낸다. **호스트 PC 는 알림 내용을 믿지 않고 서버에서 다시 읽는다**(리모컨도 같은 주소에 보낼 수 있어 가짜 콘티를 섞을 수 있으므로). 리모컨은 control 주소에서만 상태를 받는다. 보기 기기는 표시만.
  - DB 발 공개 알림(`realtime.send`, private=false)은 기록만 되고 **공개 구독자에게 전달되지 않는다**(검증으로 확인) → 쓰지 않음(마이그레이션 20261118010000).
- **비밀번호 실패 잠금 = 그 기기(브라우저)만**(5번 틀리면 1분). 서버는 잠그지 않는다 → 다른 폰이 덩달아 잠기지 않음. **인지된 위험(사용자 결정 B)**: 스크립트로 4자리 비밀번호를 대입하면 막지 못한다.
- 비밀번호 최소 4자 유지(사용자 결정).
- **콘티는 그날 하루 쓰는 임시 데이터** — 콘티 보관·다른 송출에서 가져오기 기능은 만들지 않는다(사용자 결정). 인터넷 송출은 서버에 '현재 상태'(콘티 포함)가 있으므로 나중에 필요하면 그걸로 가능성은 열려 있음.
- 곡: "곡 다운로드"(그때 로그인)로 PC 에 저장. PC 에서 고치거나 등록한 곡은 "서버에 올리기"에서 중복(가사 === / 제목 ===)·충돌(서버 updated_at) 검사 후 올림. 삭제는 온라인만.

## 새 컴퓨터에서 시작하기
```bash
git clone https://github.com/wondaero/biew.git && cd biew
nvm install 22 && nvm use
npm install
cp .env.example .env     # 값 채우기 ↓
```
`.env` 값:
- `VITE_SUPABASE_URL` / `SUPABASE_URL` = `https://bgfkodbfgjhsauwqhviq.supabase.co`
- `VITE_SUPABASE_ANON_KEY` = 대시보드 Project Settings → API Keys → **publishable** 키
- `SUPABASE_SERVICE_ROLE_KEY` = 같은 화면의 **secret** 키(또는 Legacy 탭의 service_role). import·staff·verify 스크립트에만 필요. 웹앱 개발만 하면 없어도 됨.

Supabase CLI 작업(마이그레이션 등)이 필요하면:
```bash
supabase login            # 새 계정 쪽으로 로그인(기존 계정 세션 주의 — 시크릿 창 or --token)
supabase link --project-ref bgfkodbfgjhsauwqhviq
supabase migration list --linked
supabase db push          # config push 아님!
# CLI 3.x 는 config.toml 의 [inbucket] 때문에 거부함 → npx supabase@2 ... 로 실행(config.toml 은 손대지 않음)
```
가사 원본(.gcg 폴더)은 git 에 없다. 재import 가 필요할 때만 USB 등으로 복사(`doc/` 아래에 두면 자동으로 git 제외).
`.env` 가 없어도 앱은 뜨지만 Supabase 가 `null` 이라 로그인·곡 동기화·채널 기능이 모두 안 된다(UI 확인만 가능).
